# AGENTS.md

Next.js 16 (App Router) frontend for **Admina**, a Spanish-language academic-procedures system. Ships as a **static export** wrapped in **Capacitor Android**.

## Commands

- `npm run dev` — dev server (npm is the real package manager: `package-lock.json` is tracked; the local `bun.lock` is not).
- `npm run dev:network` — dev server bound to `0.0.0.0` so the phone on the LAN can load the live-reload bundle.
- `npm run dev:android` — `cap run android -l`; run it in a second terminal next to `dev:network`.
- `npm run lint` — `eslint .` over the whole repo (no `--fix` flag in the script). Run `npx eslint <path>` to lint one folder.
- `npx tsc --noEmit` — typecheck. There is no `typecheck` script and no test suite.
- `npm run build` / `build:web` — writes the static site to `out/`.
- `npm run build:android` — build + `cap sync android`.

Verification order that works here: `npm run lint` → `npx tsc --noEmit` → `npm run build`.

## Static export constraints (the usual source of breakage)

`next.config.ts` sets `output: 'export'`, `trailingSlash: true`, `images.unoptimized: true`.

- No API routes, middleware, server-side data fetching, `next/headers`, ISR, or dynamic `[id]` segments. **No bracket folders at all.**
- Route params always travel as query params (`/request/detail?id=...`, `/request/formRequest?...`). Any `useSearchParams()` must be wrapped in `<Suspense>` — see `app/(auth)/(management)/request/detail/page.tsx` — or the build fails.
- Every page is `'use client'`. Don't introduce server components that read data.

## Backend

- `NEXT_PUBLIC_API_URL` is required and must be an absolute URL (`http://localhost:PUERTO` on web, `http://192.168.X.X:PUERTO` on a physical device — never `localhost` there). See `.env.example`; `.env` is gitignored.
- All calls are raw `fetch` to `${NEXT_PUBLIC_API_URL}/api/...` with `Authorization: Bearer <authToken>` from `localStorage`.
- Auth is client-side: `useLogin()` in `app/login/useLogin.ts` writes the session to cookies (`userSession`, `userRole`, `userToken`) plus `localStorage` (`userSession`, `authToken`). `app/(auth)/layout.tsx` only checks *logged in*.
- Roles are `Estudiante`, `Administrativo`, `Superusuario`; per-role navigation lives in `components/Shared/Navbar/Sidebar.tsx`. `hooks/useRoleProtection.ts` defines the role→route allowlist but is **not mounted anywhere** — don't assume route-level role gating is active.

## Layout conventions

- `app/` = routes. `app/(auth)/` = authenticated shell, `app/(auth)/(management)/` = admin screens.
- One feature = `page.tsx` + a colocated `useX.ts` holding both the fetch functions and the hook. There is no global API client; each module repeats its own fetch + toast handling. `app/services/requestService.ts` is the only shared service (request screens only).
- All shared types live in `app/type.ts`; zod schemas in `schemas/`; reusable UI in `components/UX/**`, chrome in `components/Shared/**`.
- Import alias `@/*` maps to the repo root.
- `<AppToaster/>` must be rendered on each page that fires toasts — it is not in the root layout.

## Platform & native shell

- `hooks/usePlatform.ts` is the only source of truth: `isNative`, `isWeb`, `isAndroid`, `isIOS`.
- Wrap JSX instead of branching inline: `<MobileOnly>` / `<WebOnly>` from `components/Shared/Platform/PlatformOnly.tsx`.
- `app/layout.tsx` mounts `<StatusBarInit/>` (native status-bar style) and imports `app/globals.css`, which holds the safe-area utilities: `.safe-top`, `.safe-bottom`, `.safe-x`, `.safe-y`, `.safe-all`. `viewportFit: 'cover'` is already set.

## UI stack

- **MUI v9** (`sx` prop; theme and status colors in `app/theme.ts`) + `@mui/icons-material`. Write MUI, not Tailwind: Tailwind v4 is wired through PostCSS but there is no Tailwind stylesheet and no `className` usage; `app/globals.css` is plain CSS (safe areas only).
- `react-router-dom` is an installed dependency but **unused** — use `next/navigation`.
- `hooks/usePlatform.ts` reports `web` during prerender; the real platform resolves after mount.

## Android

- `android/app/src/main/assets/public/**`, `assets/capacitor.config.json` and `capacitor.plugins.json` are generated by `cap sync` and gitignored. Never edit or debug against them.
- Native code is just `MainActivity.java` (app id `com.admina.app`). Gradle files are Capacitor boilerplate; app-level settings go in `capacitor.config.ts`.

## Repo notes

- No CI, no tests (`android/app/src/test` is Capacitor boilerplate). Prettier has no config file; `.prettierignore` keeps generated dirs out of `npm run format`.
- UI copy and identifiers mix Spanish and English; match the file you are editing.
- `graphify-out/` holds a generated codebase knowledge graph (`graphify query "..."`); it is output, not source.
